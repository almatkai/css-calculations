# CSS Calculations — Native V2

Standalone offline Rust engine and concrete compiled-in Tezbar adapter for `clamp_px` / **Calculate Clamp PX** and `clamp_rem` / **Calculate Clamp REM**. V1 remains intact beside V2. Original extension: **teziovsky** (no contributors listed in the pinned original manifest). Own repository metadata lists almatkai; that does not replace the original credit. The original PNG is retained byte for byte.

Native V2 is compiled-in Rust: installing `manifest.json` alone cannot install executable code. Host registration/rebuild and actual macOS/Windows UI, clipboard, focus and paste QA remain **not-run**. See [INTEGRATION.md](INTEGRATION.md) before integrating.

The five text fields, in order, are Min Font Size (`min_font_size`, empty), Max Font Size (`max_font_size`, empty), Min Viewport Width (`min_vw_width`, `375`), Max Viewport Width (`max_vw_width`, `1400`), Base Font Size (`pixels_per_rem`, `16`). PX placeholders say Pixels, REM placeholders say Rems, including viewport placeholders even though the calculation divides viewport widths by pixels per rem in both modes. The source has no preferences, command arguments, storage, shortcuts or external calculation library. `argumentValues`/`preferences` do not populate these fields.

The port preserves `Number` conversion, distinct change/submit truthiness checks, `parseFloat(value.toFixed(4))`, IEEE binary64 operation order and JavaScript number strings. It does not sort or constrain endpoint pairs. Equal endpoints can produce `NaN`/`Infinity`; zero string values and whitespace can pass submit although on-change rejects them. The exact source typo `grater` and hooks' mismatched viewport/base error keys are retained. Invalid submit blocks copying; viewport/base submit errors do not replace their previous displayed on-change errors, as in V1.

`Copy Clamp` validates the complete five-field map and copies the calculated bytes. Successful object acknowledgement displays **Clamp Copied 🎊** and the output using supported `Form.Description` nodes. This is an explicit HUD adaptation: it keeps the form/drafts open and does not implement Raycast's transient HUD or window dismissal. There is no invented HUD API. If closing the window becomes a product requirement, the pinned host's `window:hide` returns null despite hiding; fix that host route to return a strict object acknowledgement before relying on it. Do not treat null as success.

A field has an explicit 65,536 UTF-8 byte transport/resource limit; longer values return an error without truncation or state mutation. There are no invented numeric constraints. Clipboard errors/malformed acknowledgements produce an uncertain result with a bound **Retry Copy (Previous Clamp)** action. Repeating the same submission cannot automatically repeat an uncertain effect. Retry uses the prior computed output and ignores event-supplied output. Acknowledged output survives subsequent draft edits; no later persistence/hide step can misreport the copy. Runtime requires no Node, Bun, JS, subprocess or network.
